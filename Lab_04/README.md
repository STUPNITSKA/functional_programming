# Лабораторна №4. Обходи n-арного дерева

Варіант 14. Мета — розібратися з рекурсією, базовими випадками, обмеженням стеку в Python і мемоізацією через `functools.lru_cache`, а також порівняти рекурсивні та ітеративні версії.

- `algorithms.py` містить базові задачі лабораторної та варіант:
  - `quicksort` — рекурсивне сортування з випадковим pivot. База: список з 0 або 1 елемента повертається копією. Крок: розбиття на менші, рівні й більші за pivot та рекурсивне сортування двох частин. Вхідний список не змінюється.
  - `Node` і обходи бінарного дерева `preorder`, `inorder`, `postorder` як рекурсивні генератори, а також ітеративні `bfs_level_order` і `dfs_preorder_iter`.
  - `fib` з `@lru_cache(maxsize=None)`, `fib_naive` без кешу та `fib_iter` з циклом. Від’ємне `n` дає `ValueError`.
  - `TreeNode` — незмінний вузол n-арного дерева з дітьми в `tuple`. Рекурсивні `nary_preorder`, `nary_postorder` і пошук `contains`, ітеративні `nary_dfs_iter` (власний стек) і `nary_bfs` (черга), висота дерева рекурсивно `height` та ітеративно `height_iter` по рівнях. База рекурсії — порожнє дерево `None`, крок — обробка кожної дитини.
- `app.py` показує всі обходи на прикладі, порівнює час `fib(30)` без кешу, з кешем та ітеративно, друкує `cache_info()`, порівнює рекурсивну й ітеративну висоту на випадковому дереві з 50 000 вузлів і показує, що на ланцюжку з 5000 вузлів рекурсія падає. `main.py` запускає `main()` з `app.py`.
- `tests/test_quicksort.py` порівнює `quicksort` з `sorted` і перевіряє, що вхідний список не змінюється.
- `tests/test_tree.py` перевіряє послідовності обходів обох дерев, порожні дерева й дерево з одного вузла, пошук, висоту, незмінність дерева та глибоке дерево.
- `tests/test_fib.py` перевіряє перші значення, збіг з `fib_iter`, `cache_clear()` і `cache_info()` та помилку для від’ємного `n`.

## Ліміт рекурсії і TCO

CPython обмежує глибину рекурсії, за замовчуванням це 1000 кадрів (`sys.getrecursionlimit()`). При перевищенні виникає `RecursionError`. Ліміт можна підняти через `sys.setrecursionlimit`, але це ризиковано: занадто глибокий стек може завалити інтерпретатор.

Оптимізації хвостових викликів (TCO) у CPython немає: навіть виклик у кінці функції створює новий кадр стеку, тому глибина росте так само. Через це для глибоких структур ітеративна версія з власним стеком або чергою безпечніша: `height_iter` рахує висоту ланцюжка з 5000 вузлів, а рекурсивна `height` на ньому падає з `RecursionError`. Для звичайних дерев невеликої глибини рекурсія коротша й читабельніша.

`lru_cache` запам’ятовує результат для кожного `n`, тому `fib` обчислює кожне значення один раз: замість експоненційного числа викликів виходить лінійне. `fib.cache_info()` показує влучання та промахи кешу, `fib.cache_clear()` очищує кеш.

## Запуск

Для запуску потрібен Python 3.10 або новіший. З кореня репозиторію виконай `python Lab_04/main.py`.

```bash
cd Lab_04
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python main.py
python -m pytest -q
python -m mypy .
python -m black --check .
python -m ruff check .
```

У контрольному запуску `fib(30)` без кешу виконувався приблизно 0,27 с, з `lru_cache` — 0,00006 с, ітеративно — 0,000005 с. Після обчислення `cache_info()` показує 31 промах і 28 влучань. На випадковому дереві з 50 000 вузлів висота 29: рекурсивна версія — приблизно 0,019 с, ітеративна — 0,0055 с. Числа залежать від комп’ютера.
