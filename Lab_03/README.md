# Лабораторна №3. IoT-сенсори

Варіант 14. Мета — описати сенсори незмінними структурами, замінити зміни на місці оновленнями, що повертають нові об’єкти, і порівняти час роботи зі змінною моделлю.

- `model.py` містить `Reading` і `Sensor` як `@dataclass(frozen=True, slots=True)`. Показники сенсора зберігаються в `tuple`, мітки — у `frozenset`, конфігурація — у `MappingProxyType`, тобто тільки для читання. Метод `average` рахує середнє значення показників.
- `core.py` містить чисті функції. `make_config` копіює словник перед обгортанням у `MappingProxyType`, тому зміна вихідного словника не впливає на конфігурацію. `add_reading`, `add_label` і `update_config` повертають новий `Sensor` через `dataclasses.replace`. `top_by_average` повертає `tuple` сенсорів з найбільшим середнім, а `freeze` глибоко заморожує вкладені словники, списки й множини.
- `app.py` створює сенсор, додає два показники, мітку й нову конфігурацію та друкує обидві версії. `main.py` запускає `main()` з `app.py`.
- `tests/test_immutability.py` перевіряє, що оновлення повертають нові копії і не змінюють старі, що конфігурація тільки для читання, поля не можна змінити, сенсори та показники хешуються, а `freeze` працює для вкладених структур.
- `tests/test_performance.py` 20 000 разів виконує однаковий сценарій: створення сенсора, два показники, мітка і зміна конфігурації. Змінна модель на словниках змінює дані на місці, незмінна створює нові версії. Час показує `pytest --durations=5`.

`Sensor` хешується, хоча `MappingProxyType` не хешується: поле `config` позначене `field(hash=False)`. Воно враховується при порівнянні `==`, але не входить у хеш. `Reading` хешується повністю і може бути ключем словника.

Для запуску потрібен Python 3.10 або новіший. З кореня репозиторію виконай `python Lab_03/main.py`.

Щоб запустити програму й усі перевірки, перейди до папки лабораторної.

```bash
cd Lab_03
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python main.py
python -m pytest -q --durations=5
python -m mypy .
python -m black --check .
python -m ruff check .
```

У демонстрації початковий сенсор `temp-1` лишається без показників і з міткою `kitchen`, а нова версія має показники 21,5 і 22,5, середнє 22,00, мітки `critical` і `kitchen` та інтервал 30. Зміна вихідного словника після створення сенсора на конфігурацію не впливає.

У контрольному запуску змінна модель виконала сценарій приблизно за 0,01 с, незмінна — за 0,22 с. Числа залежать від комп’ютера. Незмінність коштує часу, бо кожне оновлення створює новий об’єкт і копіює конфігурацію. Натомість старі версії не змінюються, конфігурацію не можна випадково переписати, а сенсори можна класти в множини й порівнювати, що спрощує тести.
